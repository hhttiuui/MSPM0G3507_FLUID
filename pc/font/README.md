# 12×12 中文点阵字库（脱机显示用）

给 15×16 LED 点阵做**脱机中文显示**用的字库。不依赖上位机，MCU 直接从 Flash 查表画字。

源字：**文泉驿点阵宋**（WenQuanYi Bitmap Song）10pt —— 手工调的 **12×12** 点阵。
这是 12~13 像素这个尺寸下最好的中文点阵，比任何 TTF 缩下来的都清楚。

## 为什么不用 TTF 缩放

网页那边用 `fillText` 把微软雅黑画到 120×128 再缩到 15×16，效果能看但**笔画会糊**：
TTF 的笔画是按矢量轮廓 + hinting 算的，缩到 12px 时很多横竖只剩半格灰，
再走阈值就变成断续的点。而文泉驿这版是**逐像素手工调**的，每一笔都落在整格上。

| | TTF 缩到 12px | 文泉驿 12×12 点阵 |
|---|---|---|
| "国"的外框 | 有的行缺一格 | 完整闭合 |
| "繁"的多笔画 | 糊成一团 | 能认出 |
| 文件大小 | 依赖字体引擎 | 28 字节/字，纯查表 |

```
├── tools/
│   ├── build_font.py    从 BDF 重建字库（换字号也用它）
│   └── subset_font.py   从母库裁出只含你要显示的字的 .h

    └── chinese2.map     字符 → 码位 映射
```

> **常用库的 C 数组不在这个目录里**，它已经编进固件：
> `hardware/wqy12_common.h`（由 `build_font.py` 生成，可直接 `#include`）。
>

## 数据格式

小端，全部字节对齐，**MCU 侧不需要任何跨字节移位**。

```
文件头 16 字节
  0..3   "WQF1"
  4      单元宽 W        = 12
  5      单元高 H        = 14
  6      每行字节数 BPR  = 2
  7      标志           = 0
  8..9   字形数 count   （u16）
  10     基线行         = 11
  11     每字形字节数   = 28
  12..15 保留

码位表   count × 4 字节（u32，升序，可二分）
步进表   count × 1 字节（每字形占几个像素宽）
位图区   count × 28 字节
```

三个表顺序排列。因为每个字形定长，**不需要存偏移**：第 i 个的位图 = `bm + i*28`。

位图逐行从上到下，每行 2 字节，**最高位 = 最左像素**：

```c
bit = bm[y*2 + (x>>3)] & (0x80 >> (x&7))
```

## 三个用法

### 1. 直接用常用库（599 字，19.3 KB）

把 `wqy12_common.h` 拷进工程，加进 `Debug/` 的构建列表即可。

```c
#include "wqy12_common.h"

/* 在 (x0,y0) 画一个 UTF-8 字符串，返回画到第几列 */
static uint8_t DrawUtf8(const char *s, uint8_t x0, uint8_t y0, uint8_t level)
{
    uint8_t  x = x0;
    uint32_t cp;

    while (*s) {
        /* UTF-8 解码（GB2312 里的字都在 BMP，最多 3 字节）*/
        if ((*s & 0x80u) == 0u) {
            cp = (uint32_t) (uint8_t) *s++;
        } else if ((*s & 0xE0u) == 0xC0u) {
            cp  = (uint32_t) ((uint8_t) s[0] & 0x1Fu) << 6;
            cp |= (uint8_t) s[1] & 0x3Fu;
            s += 2;
        } else {
            cp  = (uint32_t) ((uint8_t) s[0] & 0x0Fu) << 12;
            cp |= (uint32_t) ((uint8_t) s[1] & 0x3Fu) << 6;
            cp |= (uint8_t) s[2] & 0x3Fu;
            s += 3;
        }

        const wqf_glyph_t *g = WQF_Find(cp);

        if (g != 0) {
            for (uint8_t gy = 0u; gy < WQF_H; gy++) {
                for (uint8_t gx = 0u; gx < g->adv; gx++) {
                    if ((WQF_PIXEL(g->bm, gx, gy) != 0u) &&
                        ((x + gx) <= LED_APP_COLS)) {
                        LedMatrix_SetCellLevel((uint8_t) (x + gx),
                                               (uint8_t) (y0 + gy), level);
                    }
                }
            }
            x = (uint8_t) (x + g->adv);
        }
    }
    return x;
}
```

### 2. 裁出只含你要显示的字（推荐）

一个"温度 25℃"的界面通常只要十几个字，裁完 **200~500 字节**：

```bash
cd font/tools
python subset_font.py --text "室内温度25℃湿度" --out ../my_font.h
#   → 结果：8 字形，280 字节

python subset_font.py --text "温度25℃" --ascii --out ../my_font.h
#   --ascii 顺带带上全部 95 个 ASCII，省得漏字母

python subset_font.py --text "室内温度" --dry-run
#   只统计不写文件
```

输出的 `.h` 结构和 `wqy12_common.h` 完全一样，**直接替换**即可。
母库里没有的字会明确列出来，不会静默丢掉。

### 3. 换字号重建

```bash
# 先下 BDF（其他尺寸）
curl -L -o font/_src/wenquanyi_9pt.bdf \
  https://raw.githubusercontent.com/larryli/u8g2_wqy/master/bdf/wenquanyi_9pt.bdf

cd font/tools
python build_font.py --bdf ../_src/wenquanyi_9pt.bdf    # 11×11
```

| BDF | 中文点阵 | 单元高 | 每字 | 母库大小 |
|---|---|---|---|---|
| `wenquanyi_9pt.bdf` | 11×11 | 13 | 26 B | ~226 KB |
| **`wenquanyi_10pt.bdf`** | **12×12** | **14** | **28 B** | **243 KB** |
| `wenquanyi_13px.bdf` | 11×13 | 15 | 30 B | ~180 KB |
| `wenquanyi_12pt.bdf` | 16×16 | 18 | 36 B | ~280 KB |

单元宽高和基线都由脚本按实际字形算，换字号不用改参数。

## 和 15×16 屏的对应关系

```
        ← 12 格字身 →  ← 3 格空 →
        ┌────────────┐
  行 0  │  ########  │
        │  #      #  │   单元 12 宽 × 14 高
        │  # #### #  │   中文占行 0~11
        │  #    # #  │   ASCII 底边落在行 11
        │  ########  │
  行 13 │            │   行 12~13 是下伸区（g j p q y 用）
        └────────────┘
```

- **宽 12，屏幕 15 列** → 一个字居中时左右各留 1~2 列
- **步进 `adv` 是 13 不是 12**（字体自带 1px 右间隙），两个汉字要 26 列，**15 列放不下**，
  所以多字必须滚动 —— 和网页那边的结论一致
- **高 14，屏幕 16 行** → 上下各留 1 行做边距最舒服

`WQF_PIXEL` 里 `gx` 最大会取到 `adv-1 = 12`，超出 `WQF_W`，但因为 `BPR = 2`
（每行 16 位），读到的只是补零的高位，**不会越界**，所以上面那段循环可以直接用。

## 许可证（重要）

文泉驿点阵宋是 **GPL v2 + 字体嵌入例外**（font embedding exception）。

这个例外就是为嵌入式场景准备的：**把字库嵌进固件不要求固件本身也开源**。
但字库文件本身仍然是 GPL v2，分发时要保留版权声明（`wqy12_common.h` 顶部已带）。
商用前建议自己再确认一遍，或者换思源黑体等 OFL 字体重建。

## 已知限制

- 母库只覆盖 **GB2312（6763 汉字）+ ASCII**。"囧""氪""怼"这类 GB2312 之外的字没有 ——
  需要的话得用 `wenquanyi_12pt.bdf`（含 20940 个 CJK 字）重建母库，但单元会变成 16×16，
  15 列装不下。
- 只有 12 像素一种字重，没有粗体。需要加粗可以用 `WQF_PIXEL(x,y) | WQF_PIXEL(x-1,y)` 横向膨胀。
- 标点用的是全角宽度（12 格），在 15 列的屏上会显得很松。

## 自检

`build_font.py` 每次跑完会把「中 国 A 1」画成 ASCII 图打印出来，直接看形状对不对：

```
  中  (adv=13)
    .....#......
    .....#......
    .##########.
    .#...#....#.
    .#...#....#.
    .#...#....#.
    .##########.
    .#...#....#.
    .....#......
    .....#......
    .....#......
    .....#......
    ............
    ............
```

生成的 `wqy12_common.h` 已经用 **tiarmclang 4.0.4（cortex-m0plus, -Wall -Wextra）**
编译验证，零警告。

**但"能编译"远远不够** —— 这里踩过一个只有上板才发现的坑：

> `emit_header()` 算位图起始偏移时用的是**旧格式**（每项 8 字节），
> 而实际布局是 `4 字节码位 + 1 字节步进` = 5 字节/项。
> 结果整个位图数组**错位 1797 字节**（599 × 3），每个字形都指向别处，
> 屏幕上是一片噪点 —— 而代码编译、链接、运行全都正常，只是画出来是乱的。

现在 `build_font.py` 和 `subset_font.py` 写完 `.h` 都会**回读并逐字节比对**
位图区，不一致直接抛错：

```
  自检通过：位图 16772 字节逐字节一致
```

改格式时如果只改 `pack()` 忘了改 `emit_header()`，这一步会立刻抓到。
