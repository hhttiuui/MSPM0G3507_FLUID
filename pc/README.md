# 上位机（Web 版）

给 15×16 LED 点阵用的**零依赖单文件**上位机。把图片 / 文字 / 手绘变成帧数据，
再通过 Web Serial 直接推给板子。

> **不需要安装任何东西，也不需要联网。** 双击 `index.html` 就能用。

---

## 怎么用

1. 用 **Chrome 或 Edge** 打开 `index.html`（Firefox / Safari 不支持 Web Serial）
2. 板子插上 USB 转串口，点「连接串口」，选对应的 COM 口（115200 8N1）
3. 选一个来源（图片 / 文字 / 内置字库 / 手绘），调好参数
4. 点「发送到板子」

没接板子也能用——「帧数据」那一栏会输出十六进制，可以复制走。

---

## 四个来源

| 来源 | 做什么 | 发什么 |
| --- | --- | --- |
| **图片** | 上传图片 → 自动缩放到 15×16，可调阈值 / 对比度 / gamma | 整帧位图（8bit 或 1bit） |
| **文字** | 输入文字 → 用系统字体渲染成点阵 | 整帧位图，或条带（滚动） |
| **内置字库** | 不渲染，直接发文本命令 | 文本命令，字形由 MCU 的 12×12 字库现场画 |
| **手绘** | 鼠标点格子 | 整帧位图 |

「内置字库」这条路很特别：**PC 端不画点阵**，只发 `text 你好世界` 这样的命令，
MCU 用自己的字库渲染。好处是能跟着重力转 90°/180°，代价是只能用固件里带的字。

---

## 输出格式

两种位深，都是**行优先**：

- **8bit**：240 字节，`idx = row × 15 + col`，值 0~255 是亮度
- **1bit**：32 字节 = 16 行 × 2 字节，每行 byte0 装 x1~x8（bit7 = x1）

外面套 6 字节头：`0xA5 | ver | flags | rows=16 | cols=15 | len`。
完整协议见根目录 `README.md` 的「串口调试」一节。

## 已知限制

这些不是 bug，是当前的边界：

- **内置字库栏不预览点阵**：字形在 MCU 里，PC 没有这份数据，预览区会显示说明文字
- **Firefox / Safari 用不了**：Web Serial 是 Chromium 独有的 API。
  这两个浏览器下仍可导出帧数据，但要自己找串口工具发
- **动图槽位有容量上限**：槽 0 是 16 KB、槽 1 是 8 KB。帧数 × 每帧字节数超了就传不进去，
  上传前会先检查
- **「存 Flash」那一行只管两种存法**：文字条带（glyph 区）和字库预设。
  图片 / 手绘走下方「存到槽位」，两者不是一回事
- **没有回读**：固件不回 ACK，发送成功只代表字节写出去了。
  要确认得看屏幕，或者发 `div 1` 打开遥测

## 字库工具链

`font/` 是生成固件里 `hardware/wqy12_common.h` 的脚本，改字号或裁子集时才需要：

```bash
cd font
python tools/build_font.py      # 从 BDF 源重建
python tools/subset_font.py     # 裁成常用字子集
```

详见 `font/README.md`。
