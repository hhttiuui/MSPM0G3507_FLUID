# 刹车高亮

> **⚠ 当前状态：已用 `BRAKE_ENABLE` 整体关闭（默认 0）。**
> `hardware/brake.h` 顶部把 `BRAKE_ENABLE` 从 `0` 改成 `1` 即可恢复，
> 其它文件一个字都不用动 —— 关掉时头文件提供同名空实现，
> `brake.c` 整段不参与编译（省 3.5 KB Flash + 320 B SRAM）。
> 关闭期间 `brk` / `brkf` 等命令是空操作，`brkthr` 这类会返回失败码。

尾灯的国标逻辑是「刹车时必须明显变亮」，但板子上**没有刹车线信号**可取。
所以从加速度计上读：刹车 = 沿行进方向**持续的减速度**。

## 检测哪个轴

尾灯竖装、屏幕朝后时，**行进方向就是屏幕法线（芯片 AZ）** —— 屏幕 x / y 都在
板面内，刹车在它们上面几乎没有分量。

实测（2026-10-27，本板竖装）：

| 轴 | 静止读数 | 含义 |
| --- | --- | --- |
| AX | **-998 mg** | 重力全压在这（屏幕 y 轴竖直）|
| AY | -14 mg | 板面内横向，≈0 |
| AZ | **+195 mg** | 法线方向，只是 11° 倾角的重力投影 |

所以默认 `brkax 2`。AZ 上那 195 mg 的倾角分量**不能直接比阈值**，
否则静止就在触发 —— 见下面的基线。

## 判定流程

```
当前轴读数 − 基线 = dev（纯运动加速度，重力/倾角已被减掉）
      ↓ 一阶低通 τ≈90 ms
decel = ±dev（符号由 brksgn 定，正 = 正在减速）
      ↓
decel ≥ 150 mg 持续 180 ms  → 进入刹车态
decel ≤  60 mg 持续 350 ms  → 退出（且已亮够 400 ms）
```

## 基线：为什么不能直接比绝对值

板子竖装总有几度倾斜（本板 11°），AZ 静止就有 195 mg。检测的是**偏离基线的量**：

```
基线 = 静止/匀速时该轴的读数（重力投影 + 安装倾角）
     每帧缓慢跟随 1/128（τ≈2.8 s），**刹车期间冻结**
```

三个好处：装歪多少都自动吸收、上下坡和车身姿态不误触发、换板不用重新量倾角。
刹车期间冻结是必须的 —— 否则刹车本身会被基线慢慢吃掉；冻结后刹车一松，
读数立刻回到基线、dev≈0，灭灯没有拖尾。

另外有个 20 s 的**安全阀**：连续触发超过 20 s 判定为误触发，强制释放并重同步基线，
避免"陡坡/磕碰"把灯永久点亮。

> ⚠ 基线是 **Q8 定点**（1/256 mg）累加的。早期直接对 mg 右移，偏差小于 2^shift 时
> 增量为 0，基线完全不动 —— 缓坡 10° 就会把灯点死。仿真复现后改的。

## 旋转门控：为什么"一竖直放就亮"

拿起、放下、装壳时板子被**转动**，重力在法线上的投影跟着变（立起来那一下
AZ 从 ~1000 掉到 ~195，相当于 800 mg 的"加速度"），基线追不上，就被当成刹车。

但**刹车本身不转动板子** —— 直线刹车时陀螺读数接近 0。所以陀螺的正确用法
不是"测刹车"，而是**判断板子正在被转动，从而屏蔽检测**：

```
|ω| > 70 °/s  →  挂起检测、清计时器、熄灭刹车灯
                 （持续 >150 ms 才认为姿态变了，重同步基线）
```

阈值 70 °/s 的依据：手持转动一般 90~300 °/s，而刹车时前叉下沉带来的俯仰
只有 5~15 °/s，差得很开。所以真刹车不会被屏蔽，拿起放下会被屏蔽。

> **为什么不用陀螺测刹车**：陀螺测的是角速度。直线刹车时板子没有转动，
> `gz` 不变化，对它微分（角加速度）更是接近 0 —— 物理上就测不到。
> 刹车是**平动**，只有加速度计看得到。

## 为什么判定用"幅值"而不是"对 AZ 微分"

加速度计确实无法分离重力和运动加速度（这是物理限制），但**微分不能解决它**，
反而更糟。用本工程的数据算一遍（`dbg.brake.dmg_mgps`，遥测 bit16 可实时看）：

| 事件 | AZ 变化率峰值 | 说明 |
| --- | --- | --- |
| 刹车 0.3 g（0.2 s 爬升）| **±1060 mg/s** | 只有起止瞬间有值 |
| 刹车 0.3 g（保持段）| **≈0** | 微分检测会在刹车中途灭灯 |
| 立起来（0.3 s 转 90°）| **-2319 mg/s** | 比刹车大一倍多 |
| 慢慢立起来（1.5 s）| -543 mg/s | 和刹车一个量级 |
| 静止噪声 ±2 mg | ±20 mg/s | 可用 |

三个结论：

1. **转动比刹车的变化率更大** —— 用微分判定，拿起板子反而更容易触发，
   等于把"太灵敏"这个问题放大。
2. **持续刹车时变化率为 0** —— 微分只能抓到起止的边沿，刹车中间会灭灯；
   想让它一直亮就得再积分回去，那就又回到了"看幅值"。
3. 微分放大噪声（46 Hz 采样下，1 mg 噪声 = 46 mg/s 的导数）。

> **代码里两种判定都实现了，默认用幅值**（`brkmode 0`）。
> `brkmode 1` 是"变化率边沿 + 保持"，响应更快（实测手推急停的边沿只持续
> 65~110 ms，幅值模式要等 180 ms 确认），但有两个已知风险：
> ① 真实刹车（0.2~0.3 g）的变化率只有 1000~1500 mg/s，比手推急停（5000~7000）
> 小得多，阈值必须压得很低才抓得到；② 阈值一低，路面颠簸（10 ms 内跳 ±500 mg
> ≈ 50000 mg/s）就会疯狂误触发。所以默认没开，等路面实测再说。
>
> ```text
> brkmode 1        # 切到变化率模式
> brkdthr 1000     # 阈值 mg/s（按路面情况调）
> brkhold 1200     # 触发后保持多久
> mask 1024        # 看 count 涨了多少次 —— 骑一圈只捏 5 次却涨了 30 次，就是颠簸误触
> brkmode 0        # 切回幅值
> ```

所以判定默认看**幅值**（decel），而"重力偏差"由**基线冻结**来补偿：
刹车期间不更新基线，重力估计就停在刹车前的那一刻，这正是"加速度补偿"的
廉价近似。真要做得更严格，正确做法是用陀螺积分跟踪重力向量（互补滤波），
但那需要维护三维重力矢量，代价远大于收益 —— 现在的基线 + 陀螺门控已经覆盖
了实际会遇到的场景。

三个机制缺一不可：

| 机制 | 作用 | 不做的后果 |
| --- | --- | --- |
| **低通 90 ms** | 滤掉踏频（~1.5 Hz）和路面颠簸 | 平路骑行时刹车灯乱闪 |
| **滞回**（进 150 / 出 60） | 阈值附近不反复开关 | 看起来像接触不良 |
| **最短 400 ms + 退出延迟 350 ms** | 点刹也看得见，松刹后后车还有反应时间 | 闪一下就没 |
| **有符号**（只看减速）| 加速不亮，只有减速才亮 | 起步猛蹬也点亮 |
| **旋转门控**（陀螺）| 拿起 / 放下 / 装壳不误触发 | 一竖直放就亮刹车灯 |

## 刹车时显示什么

默认 = **全部 240 颗 LED 满亮 + 全局亮度拉到 255**。恒流档（`cc`）不动 ——
那是装机时定的硬件电流，每帧改它会让电源纹波变大。

显示内容做成可替换的，因为"刹车该显示什么"最容易被改：

| 值 | 效果 |
| --- | --- |
| `brkdisp 0` | 全屏满亮（默认）|
| `brkdisp 1` | 下半屏满亮（预留示例，证明接口可用）|
| `Brake_SetDisplayHook(fn)` | **外部注册任意画法**（C 接口，见 `brake.h`）|

注册的画法只负责往帧缓冲里画，不要自己 Flush —— 统一由 `brake.c` 推屏。

## 为什么必须"接管显示"

场景（流体 / 文字 / 动图）每帧都会重画 DDRAM，刹车画面会被直接盖掉。
所以显示权顺序是**场景之后**：

```c
s_scenes[s_cur].tick(&in);   /* 场景画它自己的 */
Brake_Tick(&in);             /* 在刹车就盖成全屏满亮 */
```

代价是刹车期间每帧多推一次 256 B（约 1.2 ms）。

退出时要把画面**原样还回去** —— 静态图 / 文字定格 / 动图都不重绘，不还的话
屏幕会一直停在白屏。做法是进刹车时快照 256 B 帧缓冲（`LedMatrix_Snapshot`），
退出时写回 + Flush。刹车期间切了场景的话，`App_Goto` 会调
`Brake_NotifySceneChanged()` 重新快照，避免还原出上一个场景的画面。

## ⚠ 与低电保护的冲突

`battery.c` 每 2 s 熄屏 1 ms 采样电压，采完把亮度恢复成**用户设定值**。
所以刹车期间**每帧重设** BC = 255（一次命令写约 15 µs），否则会被打回正常亮度。

## 上板标定

```
div 1
mask 16384         # bit14 = rawz_mg（默认检测轴）
```

| 步骤 | 操作 | 看什么 | 怎么判 |
| --- | --- | --- | --- |
| ① 定轴 | 静止 | `rawz_mg` | 竖装时只有倾角分量（本板 195）。若读到 ±1000 说明轴选错（选到重力轴了）|
| ② 定符号 | **捏一次刹车** | `mask 8192` 看 decel | **正的大数（+200 上下）= 对了**；负的大数 → `brksgn -1` |
| ③ 定阈值 | 平路骑 5 分钟 | `mask 1024` 看 count | count 自己涨 → `brkthr 200` |

②在桌面也能做：手拿板子沿法线方向**快速前推再急停**，急停那一下就是刹车。

`brkf 1` 可以强制进入刹车态（拍摄 / 演示用），`brkf 0` 退出。
