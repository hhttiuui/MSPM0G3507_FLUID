# 场景框架与文字滚动

原来主循环是"流体写死在一个死循环里"。现在抽成了**场景表 + 统一输入包**，
加新功能（文字滚动 / 沙漏 / 游戏）只是往表里加一行。

| 场景号 | 名字 | 内容 | 命令 |
| --- | --- | --- | --- |
| 0 | 流体 | 算法 → 密度 → 灰度 → 点阵 | `dt` `iter` `pause` `reinit` `full` `edge` `gam` `lock` |
| 1 | 静态图 | 亮度阶梯 / 单点 / 填充（亮度标定）| `px` `fill` `off` `ramp` `rampg` |
| 2 | 文字滚动 | 12×12 点阵字库 → 条带 → 横向滚动 | `text` `tstep` `tms` `tlev` |

## 怎么切

| 方式 | 操作 |
| --- | --- |
| 按键 | **USER1 短按 = 下一个**，**USER3 = 上一个**（循环）|
| 串口 | `next` / `prev` / `mode <0-2>` |

切换后的结果看 `dbg.app.scene`（当前场景号）和 `dbg.app.switches`（累计切换次数）。
如果按了键但 `switches` 不涨，说明按键边沿没进来，去看 `dbg.key`。

**串口上确认**：遥测第 9 路就是场景号（`mask 256` 只开它，或 `mask 271` 一起看 fps）：

```
mask 256
div 2
```

然后在终端里按 USER1 / USER3，那一路数字应该在 0 / 1 / 2 之间循环。

## 场景 2：脱机中文文字滚动

不依赖上位机，MCU 自己用点阵字库渲染中文并滚动。

```
mode 2
text 你好世界      # 换文字（UTF-8，最多 32 字节 ≈ 10 个汉字）
tstep 1           # 每帧移动 1 像素（1~8）
tms 40            # 帧间隔 40 ms = 25 fps（10~500）
tlev 255          # 文字亮度（0~255）
```

**看不清的时候用定格检查**：

```
tstep 0           # 停止滚动
tpos 0            # 跳到某个位置（0 ~ 条带宽度+15）
```

`tpos` 每加 1 就左移 1 像素，配合 `tstep 0` 可以把任意一段字停在屏幕上看清楚。
判读：**能认出字 = 字库和渲染都对**；**一排空心方框 = 字库里没有这些字**；
**完全是噪点 = 位图数据坏了**（见下面字库自检那条）。

**字库**：`hardware/wqy12_common.h`，文泉驿点阵宋 **12×12**，599 个字形
（ASCII + 574 高频字 + 常用标点），占 **19.6 KB Flash**。

> ⚠️ 这个头文件曾经有个致命的生成 bug：`emit_header()` 里算位图起始偏移
> 用的还是旧格式（每项 8 字节），而实际布局是 `4 字节码位 + 1 字节步进`。
> 结果整个位图数组**错位 1797 字节**，每个字形都指向别处，屏幕上是纯噪点 ——
> 但代码能正常编译，光看编译结果是发现不了的。
> 现在 `build_font.py` 写完 .h 会**回读并逐字节比对**位图区，不一致直接报错。

为什么不用 TTF 缩放：12 像素下 TTF 的笔画只剩半格灰，二值化后变成断续的点；
这套字库是逐像素手工调的，每一笔都落在整格上。

⚠️ **常用库覆盖不全** —— 实测「温」就不在里面。缺字会画成**空心方框**，
一眼能看出是"字库没有"而不是"排版坏了"。要显示的字固定的话，用
`font/tools/subset_font.py` 从母库裁一个专用字库最稳（几十个字只要几百字节）：

```bash
cd C:/Users/26447/Desktop/pc/font/tools
python subset_font.py --text "室内温度湿度" --out ../my_text.h
```

然后把 `my_text.h` 覆盖到 `hardware/wqy12_common.h` 即可（宏名一致）。

**自动跟随摆放方向**（`torient 4`，默认）

设备侧着放时字也跟着转，观看者始终能正着读。方向由重力判定：

| 重力 `(ax_slow, ay_slow)` | 设备姿态 | `rot` |
| --- | --- | --- |
| `(0, +9.8)` | 正放 | 0 |
| `(+9.8, 0)` | 顺时针 90° | 1 |
| `(0, -9.8)` | 倒放 | 2 |
| `(-9.8, 0)` | 逆时针 90° | 3 |

判定有**迟滞 + 稳定确认**：主导轴要超过次轴 **1.4 倍**（≈ ±35° 以内）才算数，
且新方向要连续保持 **500 ms** 才生效。否则你把板子斜 45° 看的时候，字会在两个
方向之间来回翻。

⚠️ **旋转后屏幕宽高会换**：应用网格 15 宽 16 高，正放时物理 15×16，侧放时
物理 **16×15**。所以滚动窗口宽度随方向变（`WinWidth()`），字高 12 在两种情况
下都放得下（最短边 15）。竖直偏移也跟着变：16 行时留 2 行边距，15 行时留 1 行。

板子固定安装后建议 `torient <0-3>` 锁死，免得转个角度看它就跟着翻。

**纵向对齐**：字库单元 12 宽 × 14 高，CJK 字身占 cell 的 0~11 行。条带里
**不烘竖直偏移**（glyph 固定在行 0~13），偏移在画的时候按方向加 —— 因为可用
高度会随方向变。正放时偏移 2，字身落在屏幕 3~14 行，上下各留 2 行。

**许可证**：文泉驿是 GPL v2 **+ 字体嵌入例外**。嵌进固件不要求固件本身开源，
但字库文件仍受 GPL 约束（分发要保留声明，header 顶部已带）。

## 三条设计约束

1. **同一时刻只有一个场景能写 DDRAM。** 两个场景同时写会得到两幅画叠在一起的花屏，
   而且只在切换瞬间出现，极难复现。切换时强制 `Clear + Flush` 就是把上一幅擦干净 ——
   DDRAM 是持久的，没人擦过的地方会一直亮着。
2. **场景的 `tick()` 必须非阻塞。** 禁止 `while` 等硬件、禁止 `mspm0_delay_ms`。
   一旦卡住，按键和关机全失灵（只有 TIMA0 中断那条路还活着）。
3. **场景的 `enter()` 必须自己初始化自己的状态。** 小场景共用一块 scratch，
   不要假设进来时是干净的（可能是上一个场景留下的）。

## 切回流体时液体不会重置

`FluidScene_Enter()` 只在**第一次**进来时调 `Fluid_Init()` + 预热一步。
之后切回来只复位 `pause` / `lock` / 统计，**不动粒子** —— 液体保持上次的形态接着流，
看起来像"暂停了一下"而不是"重来一摊"。想强制重来就发 `reinit`。

## ⚠ 工作流变了：`px` / `fill` / `ramp` 要先切场景

以前这几条命令是在流体场景里发的，靠 `lock 1` 冻结渲染才留得住画面。
现在必须**先切到静态图**：

```
mode 1        # 或按 USER1（短按）
ramp          # 进来时已经自动画了一次，这条是幂等的
bc 255        # 全局亮度，任何场景都能调
px 8 8 128    # 单点
mode 0        # 切回流体
```

好处是 `lock` 这个概念在静态图场景里不需要了 —— 场景本身就不会被别人覆盖。
`lock` 仍然保留，但只在流体场景里有意义（冻结渲染，方便静态测量）。
